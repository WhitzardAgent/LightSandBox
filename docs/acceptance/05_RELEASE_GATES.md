# 阶段与发行门禁

本包所有产品任务从planned开始。任何任务都必须经过实施、真实测试、独立审查与集成，才能进入verified。

## G0：事实和范围

源码/SDK/spec锁、宿主主动探测、完整任务manifest、字段使用清单和oracle可用性台账。缺失时阻止依赖它的实施任务；不阻止T00等独立工作。

## G1：最小真实路径

固定OCI镜像 → API创建 → runc → 有效命令/退出码 → 文件输出 → 审计回收。实际镜像entrypoint与requested resources得到保留；平台依赖不符合时明确拒绝。

## G2：功能和协议

exec、会话、PTY、文件、网络、groups、build、snapshot、TTL与故障恢复测试全部齐备。固定原版OpenSandbox SDK针对候选执行，协议覆盖报告列出支持/不支持项和实际证据。不能以更换import掩盖不兼容。

## G3：完整任务兼容

按完整manifest重算三个基准的三维指标。所有目标任务被登记并执行；仍有asset/oracle/reference/host阻塞时不能声称完整100%。Cyber代理和验证runner的无Docker状态分别验证。记录未知任务类型带来的范围冲突，解决后发布。

## G4：安全与性能

安全审查、资源残留、故障恢复、鉴权与不可信文件处理门禁通过；性能报告满足登记SLO且不降低相同安全/日志语义。高危P0/P1问题不以“后续修复”带过。

## G5：可安装可运维

干净机器安装、升级/回滚、锁文件、许可证清单、SBOM/制品哈希、运维说明、独立签发的测试证据与限制列表齐备。实际通过的宿主组合逐项列出。

## 验证责任

实施代理可以报告implemented并提交证据候选。集成者依据受保护CI和独立审查更新verified。状态JSON及本包脚本可发现结构错误，但不能抵抗拥有仓库写权限者伪造证据。生产开发必须把门禁放到受保护分支、可信runner和受控制品存储；不能仅依靠提示词。

`tools/packctl.py release-check`只是规划状态的阻断检查，不能代替以上正式验收。在本包初始状态它应失败，因为源码未锁定、产品未实现、全量ledger不存在。把这个失败修成“默认成功”违反合同。
