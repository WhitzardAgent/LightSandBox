# 上下文分配与跨会话交接

根AGENTS只作目录和边界。完整规范留在docs，按当前工作包加载。这借鉴短入口与渐进披露，避免每次把全部设计装进上下文。[S01][S04]

## 读取顺序

第一层：AGENTS、START_HERE、当前状态与Git差异。第二层：一张任务卡、其必需设计和特定测试编号。第三层：相关代码、实际锁定上游文件和最近失败日志。只在跨模块问题出现时扩展范围。

`packctl context Txx`输出必读文件、写入范围、依赖产物和测试清单。它不自动拼接全部日志，也不将未锁定网页当规范。极长日志先读取结构化摘要和错误附近范围，必要时跟进原始完整制品。

## 文档的四种职责

目标与设计回答“应该是什么”。任务卡回答“本次具体改什么”。执行计划回答“当前怎么做和遇到什么”。状态/证据回答“实际做到了什么”。不要让四者变成同一份反复复制的长文件。[S02][S03]

## 交接必须包含

任务ID、代码commit/dirty diff状态、已执行的准确命令和退出码、对应证据路径、未解决失败、仍活跃资源与租约、决策变更、下一步最小动作。长推理不进入交接；可复核事实进入。

新会话先验证交接中的commit与工作树是否一致，再运行小型健康检查。不能因为上一个代理写了“完成”就跳过验证。压缩上下文后重新读取边界和当前任务，不把模型内部记忆作为事实来源。

## 上下文预算规则

任务相关文档控制在少量文件；共享设计只引用，不在所有卡里复制。每张卡应自带其验收条件和输入/输出接口摘要，读者无需阅读此前会话。库内部细节按调用链定位，避免全仓dump。若一个任务需要持续加载大量无关模块，优先检查模块边界或拆分任务。
