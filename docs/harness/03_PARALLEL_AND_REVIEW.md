# 并行开发、集成与独立评审

## 并行由依赖图决定

先冻结核心类型和外部协议，再并行image/rootfs、exec/files、network、conformance等分支。每个工作分支明确owner、允许路径与依赖版本；共享types/catalog/migrations由集成者串行合并。没有子代理工具时，同一代理按同样任务图串行执行。

Git worktree只隔离源码文件。它不隔离宿主mount、netns、防火墙、cgroup、端口和Docker daemon。真实运行时测试必须使用独立worker VM或受控节点租约、唯一instance ID、独立数据目录和不重叠IPAM；默认每节点只允许一个会修改全局状态的测试批次。

## 独立审查的三个视角

规格审查核对行为是否符合任务和固定上游。系统安全审查核对权限、FD、路径、竞争窗口、身份与cleanup。测试审查检查是否真正执行、是否有负控、是否用候选自写解释器掩盖两边错误。

同一模型的新会话可以提供不同上下文的审查，但不等同于独立机构安全评估。重要安全边界需要有系统经验的工程师确认，或由受保护的独立验证流水线给出证据。

## 合并条件

独立评审直接读取diff、测试和原始结果，不只读实施者摘要。报告按照blocker/major/minor分类；涉及权限提升、失控网络、结果伪造、资源残留或判据变更的问题阻断合并。

评审不直接在实施worktree改代码。修复由实施分支完成，重新跑相关检查。集成后执行合并commit上的回归，不能拿分支旧commit结果替代。

## 权限与保护文件

上游锁、任务manifest、官方verifier摘要、CI门禁、status verified更新和发行报告设为受保护变更。允许合理更新，但需要明确原因和不同责任人的批准，不把它们设为永不可改导致维护困难。

## 高并行的上限

每条任务根据实测测试节点、上下文和依赖容量并行。禁止为了最大代理数量同时修改核心生命周期。早期保持少量并行，能减少冲突与隐藏语义漂移。吞吐以通过独立验收的功能计量，不以提交数或代码行数计量。
