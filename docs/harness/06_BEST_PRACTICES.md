# 外部最佳实践如何应用到本项目

本节只提炼对本项目有用的方法。来源是经验报告，不是某个模型可以自动正确开发沙盒的保证。

| 来源 | 吸收的方法 | 本项目的具体产物 |
|---|---|---|
| OpenAI Harness engineering [S01] | 短入口、仓库知识可检索、架构约束可检查 | 小型AGENTS、task context、依赖检查和真实运行日志 |
| OpenAI长任务指南 [S02] | 目标、实施计划、操作规则与进度分离 | design、plans、harness、state四类文件 |
| OpenAI ExecPlans [S03] | 自包含执行计划、明确验证与决策 | 每张任务卡和逐会话ExecPlan |
| OpenAI AGENTS指导 [S04] | 按仓库/目录加载相关约束 | 根目录短指引，不要求读全包 |
| Anthropic长程harness [S05] | 初始化与增量会话分开，留下可接续产物 | BOOTSTRAP/CONTINUE、结构化状态、handoff |

针对安全runtime，额外采用严格合并门禁、负控测试、完整任务台账、特权测试资源租约和判据保护。这里没有照搬任何文章中适用于普通产品的宽松合并策略，也不把“不断重试直到绿色”作为正确性机制。

代理运行品牌和模型可替换。任务卡、测试合同与证据格式才是稳定接口。没有多代理能力时按任务图串行，仍然使用新上下文评审和CI门禁。无需为适配Codex再建设一个独立通用agent平台。
