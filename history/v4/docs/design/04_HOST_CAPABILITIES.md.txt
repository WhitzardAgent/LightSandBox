# 04 宿主能力、权限与部署组合

## 首个必须验证的环境

使用现有Linux虚机，无`/dev/kvm`，不更换内核。管理员授权一个专用数据目录、运行目录、cgroup子树和网络资源范围。不能从“Docker能运行”推断全部能力可用，也不能把rootless和rootful的验收混为一谈。

`tools/doctor_readonly.py`只观察环境，不证明容器能力。T03开发的主动探测在授权测试目录创建最小资源，验证后清理。每个结果有`observed / verified / unavailable / blocked_permission`，记录工具版本、限制和原始输出。

## 探测矩阵

| 能力 | 必须验证的行为 | 失败处理 |
|---|---|---|
| mount/PID/IPC/UTS/network namespace | 创建隔离实例、看到不同命名空间、回收 | 阻止完整模式启动 |
| 用户与capabilities | uid/gid、组、cap集合真实生效 | 不能请求后忽略 |
| cgroup CPU/内存/PID | 子进程进入正确组；限额确实生效 | 必需控制器缺失时拒绝 |
| freezer | 全部任务停止推进，再恢复 | pause能力关闭 |
| seccomp/LSM | 规则真正限制测试操作，记录LSM拒绝 | 不能自动使用unconfined |
| OverlayFS | mount、copy-up、whiteout、权限、清理 | 测试其他驱动 |
| FUSE | 设备、辅助工具和权限可用，实际mount成功 | 无设备则不尝试冒充 |
| reflink/完整复制 | 元数据与隔离保持，复制规模可接受 | 不承诺性能等价 |
| 网络管理 | netns、veth/bridge、IPAM、DNS、规则安装 | 不能自动改成host network |
| 磁盘限额 | 超额写入被内核/文件系统限制 | 轮询统计不能标为硬限额 |
| 二进制兼容 | runc/helpers在现有libc和架构上启动 | 提供适配构建或明确不支持 |

cgroup文件存在不代表控制器已委派或限制有效。[S13] v1/v2分别报告；仅在所锁定runc、库与目标宿主实际支持时认证对应路径，不为纸面支持牺牲正确性。

## 配置组合

`vm-rootful-parity`：完整隔离与目标任务需要的能力，首个发行基线。

`vm-rootless-tested`：按宿主实际委派与用户命名空间权限认证，维护独立差分结果；不能直接继承rootful报告。

`development-no-runtime`：仅运行文档、类型与单元测试，不允许运行不可信命令。它不能对外暴露为可执行沙盒。

## 降级规则

文件系统驱动可在语义测试通过后切换，并公开`storage_driver`。安全隔离、出口限制、硬配额、凭据保护属于必需条件，不能降级。若目标任务要求宿主无法提供的能力，任务状态保留为`blocked_host`，完整目标仍未完成。

## 资源预算

分开设置驻留沙盒数、活跃执行数、镜像构建数和日志/文件传输并发。CPU按配额计算，内存按承诺策略与实际峰值分别管理。保留宿主、API、broker和页缓存的余量；避免用`总内存/空沙盒RSS`推算真实任务吞吐。

## 当前未知项

目标VM具体内核配置、是否有sudo、cgroup委派和可用存储尚未由本包实测。T03输出实际报告后，才能建立第一份受支持宿主声明。安装器只检查和报告，不自动换内核、关闭LSM或修改全局安全策略。
