## 推荐采用顺序

先保留seed独立测试，阅读不变量，然后把类型和状态逻辑迁入Rust目标模块。不要批量复制成最终产品；例如SQLite journal需要与真实操作记录、broker收据一起设计事务边界。复制时保留最小失败用例并补真实差分测试。

Python provider和只读工具可以沿用模块结构。原生客户端需要完成构建上传、启动等待、文件安全传输、完整输出流、认证与取消收据。代码中的Protocol代表这个接口边界，不是后端已存在。

## 直接运行

```bash
python3 dev/check_seeds.py
python3 -m unittest discover -s tests/pack -v
python3 tools/harbor_inspect.py inspect-harbor examples/harbor/minimal
# 在拥有Rust工具链的开发机上，补做下列检查：
cargo test --manifest-path seed/rust/ls-core-seed/Cargo.toml --offline
```

本包代码不包含真实漏洞PoC、外部攻击行为或有权限的容器操作。所有测试使用临时本地文件和明确替身，避免在未经授权的工作节点改变网络、mount或内核设置。

开发启动器目前要求operator保证PATH入口与当前Python的Harbor为同一安装，正式的入口身份绑定仍由T39实现并测试。Harbor真实导入、正式客户端transport、容器执行均未在本轮验证。
