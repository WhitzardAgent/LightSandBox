## 执行步骤

- [ ] 查看Git状态、任务依赖和源锁。只读本任务必要上下文，保留用户已有工作。
- [ ] 将下表输入/操作/观察固化为真实测试，先得到与目标缺失相关的失败。
- [ ] 枚举全部发布/split/task ID并保存原始总数；明确SWE各子集关系和TerminalBench发布，不采用记忆中的数量。
- [ ] 解析Dockerfile/Compose/任务配置，逐项登记capability、volume、网络、verifier形态和设备；未知字段显式保留。
- [ ] 区分oracle可用/缺失/尚未验证，Cyber代理与verifier分列；生成字段覆盖canary并写选择理由。
- [ ] 运行相关真实层与全部本地测试，保存原始日志/退出码/收集数。无权限或资产记blocked，不修改判据。
- [ ] 自审diff并独立review，提交后按handoff模板交接；未经验证不改verified。

## 必须验收的行为

| ID | 前置 | 操作 | 观察 |
|---|---|---|---|
| T02-C01 | 有不支持字段的任务 | fixture含devices、ulimits和未知Compose字段 | 任务仍在manifest，能力缺口清楚列出 |
| T02-C02 | 缺少oracle的任务 | fixture无solution或有效PoC | 保留任务并标ORACLE_UNAVAILABLE，不计正向通过 |
| T02-C03 | 重复/遗漏ID | 输入manifest重复ID或与上游完整枚举差一项 | 一致性门禁失败且给出差集 |
| T02-C04 | canary和全量 | 按字段生成canary并重算完整集合哈希 | canary只改变开发子集，不改变发行分母 |

## 命令与证据

当前可以执行：

```bash
python3 tools/packctl.py validate
python3 dev/check_native.py
python3 dev/check_seeds.py
```

产品runner由T00实现。完成后本任务使用：

```bash
./dev/check unit
./dev/check runtime --task T02 --worker WORKER_ID
./dev/check differential --task T02 --worker WORKER_ID
```

后两条需实际授权worker；本包没有这些产品命令，不能以echo或mock替代。特定本地合同任务先用真实跨语言/协议fixture，runtime层条件不具备时如实阻塞。
