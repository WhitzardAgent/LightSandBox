## Findings

### F-01 — MAJOR — Witness-exec timeout kill-switch is dead when `identity=None`; caller hangs, payload leaks (T10)

- **Trigger:** `RuncWitnessExecPort` constructed with `identity: None` — explicitly the documented *production* mode ("production deployments already run the worker as the unprivileged user", `crates/ls-host/src/runtime/native/runc.rs:78-80`; `ManagerConfig.runtime_identity: Option`, used conditionally at manager.rs:651).
- **Defect chain:**
  1. `setpgid(0,0)` is installed **only** inside `if let Some((uid,gid)) = self.identity` — `crates/ls-host/src/exec/mod.rs:321-339` (comment at :330-332 claims the group kill reaches descendants).
  2. Timeout path unconditionally `sys::kill(-pid, 9)` and ignores the result — exec/mod.rs:466-470. Without setpgid, the child's pgid is the manager's own group ≠ pid → `kill(-pid)` = ESRCH, silently dropped.
  3. After a bounded 2 s reap grace (:472-475) the code joins both capture threads with **no timeout** (:497-506) on the assumption "pipes hit EOF when the group died" (:497) — false here: the still-running runc CLI holds the pipes, so `join(stdout_t)` blocks until the guest payload exits *naturally* (potentially never, e.g. `while :; do :; done`).
- **Observed/supported impact:** a synchronous `start_execution` with a 400 ms timeout can hang **forever** instead of returning `TimedOut`/Unknown; the witness + payload keep running inside the live sandbox (CPU/resource leak) until sandbox delete. Timeout→Unknown truth is honest *if the call ever returns* — liveness and the orphan guarantee are broken.
- **Test gap:** every REAL-tier construction passes `Some(NOBODY)` — tests/exec.rs:225-243, exec/mod.rs drift-guard test; `identity=None` is never exercised anywhere.
- **Suggested fix:** always `pre_exec setpgid(0,0)` regardless of identity (keep setgid/setuid gated); *and* bound the capture join (e.g. join with timeout or kill-then-close-pipes) so a kill failure degrades to TimedOut + leaked-process audit, never a hang.

### F-02 — MAJOR — Native/runc assumptions leak into the backend-neutral manager (Q1)

`SandboxManager` is the seam that a UML backend (ADR 0002) must plug into, but it imports and re-implements native-only protocol:

1. `crates/ls-host/src/runtime/manager.rs:33` — `use crate::runtime::native::{instance_label, parse_receipt, runc};`
2. `manager.rs:631` — guest hostname derived from the **native** label grammar `instance_label(sandbox_id, generation)`.
3. `manager.rs:652` — direct call to **runc-module** helper `runc::chown_tree(lease.sandbox_dir(), …)` for PORTABLE_ROOTLESS identity chown.
4. `manager.rs:987-991` + call sites `:731`, `:1073-1075`, `:1230` — `read_init_receipt()` reads `rootfs/.lsbx/receipt.json` directly and parses with `native::parse_receipt`, **bypassing the trait method** `SandboxBackend::init_receipt` (`backend.rs:215`). The trait method is implemented (`native/mod.rs:399-407`) and stubbed in tests (`tests/lifecycle.rs:259-261`) but has **zero callers** — grep-verified.
- **Impact:** the guest-init receipt wire format (a native-backend artifact) is hard-coded into manager create/inspect/delete; a second backend must either reproduce `/.lsbx/receipt.json` semantics byte-for-byte or touch manager code. The seam exists but is dead — backend-neutrality is weaker than claimed.
- **Suggested fix:** delete `read_init_receipt`; call `self.backend.init_receipt(&instance)` everywhere; move `instance_label`-derived hostname and chown behind backend hooks (or make them backend-provided fields of `BackendInstance`).

### F-04 — MINOR — WaitInvariantBroken downgrade mislabels the wire and contradicts its own cross-check (T10, Q3)

- Guest downgrades a broken wait invariant to a **SPAWN_FAILED** receipt (`ls-guest/src/init/mod.rs:577-579`), whose documented meaning is "the payload never ran" (`init/mod.rs:219-222`) — but for WaitInvariantBroken the payload *did* run; its truth was lost.
- Host `parse_receipt` has no `WAIT_INVARIANT_BROKEN` arm (`native/mod.rs:488-503`, `_ => return None`), so `InitReceiptTermination::WaitInvariantBroken` (`backend.rs:132`) is **dead on the wire**, and exec/mod.rs:545-550 + `:570 unreachable!()` can never fire.
- If the path ever triggers, the witness exits 70 (`init/mod.rs:375`) while a SPAWN_FAILED receipt implies expected CLI code 127 (exec/mod.rs:544) → the cross-check (exec/mod.rs:552-560) converts the event into `InternalFailure` "witness/CLI disagreement" instead of a clean classification. Loud, never silent — but the receipt itself lies about "never ran".
- **Suggested fix:** emit a real `WAIT_INVARIANT_BROKEN` termination kind (with expected code 70) in a receipt protocol bump, or intentionally keep the downgrade but exit 127 to stay self-consistent.

### F-07 — MINOR — T08 backend-exec surface truth edges

1. `ExecTermination::Exited(code)` with `code = status.code().unwrap_or(-1)` — `native/mod.rs:389` via `:471-475`. If the runc CLI itself dies by signal (unrelated to the payload, e.g. host OOM), the manager reports **Exited(-1)**: a fabricated negative exit code, contradicting `backend.rs`'s "reaped normally with this code" (the exact hazard T10's WitnessLost fixes). Rare but a truth mislabel.
2. Capture-thread joins use `.unwrap_or_default()` (`native/mod.rs:376-377`): a panicked reader thread yields empty stdout/stderr with `truncated=false` — silent evidence loss.
3. stdout/stderr are `from_utf8_lossy` `String`s by type (`backend.rs:105-112`) — byte-lossy by design, disclosed in T10 EXPECTATIONS; named here because the only *wired* exec at HEAD goes through it (F-05).

### F-08 — MINOR — Foreign-container invisibility and no reaper (cleanup, Q5)

`enumerate_live` on error prints a warning and returns `Vec::new()` (`native/mod.rs:446-456`) → a transient `runc list` failure makes foreign `lsbx-*` containers invisible to the reopen report (`manager.rs:420-436`). By design those foreign instances are "reported, never adopted" — and also **never reaped**, so any leftover (crash between backend create and record write, or another manager's) accumulates with only a log note and no operator sweep tool. The lease-GC on open (manager.rs:331-345, mount-leak-refusing `sweep`) covers rootfs residue, not live containers.

### F-09 — NIT — Durability asymmetry: manager records lack fsync

`write_record` does tmp+rename but no file `sync_all`/dir sync (`manager.rs:518-534`), while the guest receipt writer is fsync-hardened (`ls-guest/src/init/mod.rs:243-262`). Crash can lose the latest hop (e.g. post-create register step); the in-memory journal cannot roll back after a crash (disclosed in comments). The lease sweep + foreign-instance report absorb the residue — acceptable, but the asymmetry deserves one explicit sentence in the durability docs.

### F-10 — NIT — Shared-state poisoning: fail-stop panic, no PanicHook/recovery

Exec registry locks `.expect("exec registry poisoned")` (exec/mod.rs:734, 786, 836), admission ledger `.lock().unwrap()` (ls-core admission :316, :349, :370, :380). A panic under lock poisons all later execs/admissions with panics instead of a controlled error. Fail-stop is honest; name it as the designed behavior (in-process v1) or wrap with `into_inner()` + explicit `backend_error`.

### F-11 — NIT — Unreachable-but-fabricating fallback exit 255 in guest decode

`child_outcome` maps an undecodable wait status to `ObservedExit::Exited(255)` (`ls-guest/src/init/mod.rs:426-431`). Without `WUNTRACED` the kernel never reports a stopped status, so this is unreachable — but if that contract ever shifts, receipt would carry a fabricated 255. Prefer an honest `WaitInvariantBroken` variant there.

### F-12 — NIT — Vacuous assertion in T10-C02

`tests/exec.rs:488`: `big_o.output.stdout[..100].windows(101).all(|_| true)` is unconditionally true (empty window set). The "prefix intact" check asserts nothing.
